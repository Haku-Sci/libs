# Review calibration — learned from the user's feedback

How `reviewer` reviews: findings to drop, points to always check, severity adjustments. Coding rules do not go here (they go in `code.md`, `front.md`, `backend.md` or `contracts.md`, where developers apply them too).
Entries are added only through `/teach-reviewer` or from feedback on a `/qa` report, always after the user approved the wording.

Format:
```
## REVIEW-<n> <short title>                      (<YYYY-MM-DD>, scope: <service | all>)
Kind: ignore | check | severity
Why: <the user's reason>
Example: <file or case it came from>
```
